# Local AI tooling info

This file documents AI-assistant configuration that lives in this repo but isn't
part of the application itself. It's here so anyone opening the repo (human or
agent) can see where this configuration came from and how to use it, without
having to dig through `CLAUDE.md`.

## Origin: the `mattpocock-skills` Claude Code plugin

The `## Agent skills` section in `CLAUDE.md` and the files under `docs/agents/`
were generated by the `setup-matt-pocock-skills` skill, part of the
[`mattpocock-skills`](https://github.com/mattpocock/skills) Claude Code plugin
(author: Matt Pocock, https://www.aihero.dev). It is installed locally as a
Claude Code plugin — nothing about the plugin itself is checked into this repo,
only the per-repo config files it wrote.

The plugin bundles skills for spec/ticket workflows, TDD, code review, domain
modelling, debugging, and general engineering process. Skills are invoked with
`/skill-name` in a Claude Code session, or picked up automatically when a
prompt matches their trigger description.

### Skills included in the plugin

Engineering:

- `ask-matt` — ask a question in Matt Pocock's voice/style
- `diagnosing-bugs` — diagnosis loop for hard bugs and performance regressions
- `grill-with-docs` — stress-test a plan/decision against this repo's domain docs
- `triage` — apply the five canonical triage labels to incoming issues
- `improve-codebase-architecture` — architecture audit and improvement flow
- `setup-matt-pocock-skills` — scaffolds the per-repo config these skills read
  (issue tracker, triage labels, domain docs) — this is what generated the
  files described below
- `tdd` — test-driven development (red-green-refactor)
- `to-spec` — turn a ticket/issue into an implementation spec
- `to-tickets` — turn a spec/discussion into tracker issues
- `wayfinder` — map-and-child-ticket workflow for open-ended exploration
- `implement` — execute a phased implementation plan
- `prototype` — throwaway prototype to answer a design question
- `research` — investigate a question against primary sources, write findings to a file
- `domain-modeling` — build/sharpen `CONTEXT.md` and ADRs
- `codebase-design` — vocabulary and process for designing deep modules
- `code-review` — review a diff against this repo's coding standards and spec
- `resolving-merge-conflicts` — resolve an in-progress merge/rebase conflict
- `wizard` — generate an interactive wizard for human-only setup steps

Productivity:

- `grill-me` / `grilling` — stress-test a plan or idea via adversarial questioning
- `handoff` — write a handoff doc for another person/session
- `teach` — explain a concept back to you to check understanding
- `to-questionnaire` — turn open questions into a structured questionnaire
- `wait-what` — plain-English breakdown of something technical
- `writing-for-agents` — guidance for writing skills, `AGENTS.md`, `CLAUDE.md`

## What was added to this repo

- **`CLAUDE.md`** — a new `## Agent skills` section pointing at the docs below.
- **`docs/agents/issue-tracker.md`** — tells the skills above that this repo's
  issue tracker is GitHub Issues (`github.com/rsanders/opentelemetry-demo`),
  and gives the exact `gh` CLI conventions to use for creating, reading,
  labeling, and closing issues (plus wayfinder map/child-ticket conventions).
  External PRs are *not* treated as a triage surface (left at the default).
- **`docs/agents/domain.md`** — tells the skills how to consume this repo's
  domain documentation (`CONTEXT.md`, `docs/adr/`) before making changes.
  Configured single-context (one `CONTEXT.md` + `docs/adr/` at the repo root).
  Neither file exists yet — `domain-modeling` creates them lazily the first
  time a term or decision actually needs recording.

Triage labels (`docs/agents/triage-labels.md`) were **not** configured, because
the `triage` skill was not installed in the session that ran the setup.
Re-run `/setup-matt-pocock-skills` later if you install it and want labels
configured.

## How to use this

- Skills are invoked directly, e.g. `/code-review`, `/tdd`, `/to-spec`.
- Skills that read repo config (issue tracker, domain docs) do so automatically
  by reading `docs/agents/*.md` — no need to repeat that context in your prompt.
- You can hand-edit `docs/agents/*.md` at any time; the skills read them fresh
  each time.
- To reconfigure (e.g. switch issue tracker, add triage labels once `triage`
  is installed, or move to a multi-context domain-doc layout), re-run
  `/setup-matt-pocock-skills`.

## Relationship to `AGENTS.md`

This repo's `AGENTS.md` sets project-wide policy for AI-assisted contributions
(no AI-authored text in issues/PRs, telemetry-schema conventions, commit
`Assisted-by:` trailers, etc.) and is unrelated to the `mattpocock-skills`
plugin — it predates this setup and applies regardless of which AI tool or
skills are in use. The `## Agent skills` block in `CLAUDE.md` only tells
Matt Pocock's skills where to find repo-specific config; it does not change or
supersede any policy in `AGENTS.md`.
